# قائمة نشر واعتماد V12.2

- [ ] مشروع Supabase جديد أو بيئة تجريبية منفصلة.
- [ ] تنفيذ `supabase/database_complete.sql` كاملًا بلا أخطاء.
- [ ] عند الترقية من V12.1، تنفيذ كتلة `V12.2 — Edge-orchestrated backup release metadata` فقط ثم نشر `backup-manager`.
- [ ] عند الترقية من V12.0، تنفيذ الملف من علامة `V12.1 — resumable application backup / restore V3` حتى النهاية على نسخة تجريبية أولاً.
- [ ] عند الترقية من V11، تنفيذ الملف من علامة `V12.0.0 — single-database reliability` حتى النهاية على نسخة تجريبية أولاً.
- [ ] إنشاء أول مستخدم Auth ثم `bootstrap_first_admin`.
- [ ] ضبط `supabaseUrl` و`supabaseAnonKey` فقط في `js/config.js`.
- [ ] نشر `create-user` و`reset-user-password` و`gemini-assistant` مع `--no-verify-jwt` وفق `supabase/config.toml`.
- [ ] نشر `backup-manager` بالأمر `supabase functions deploy backup-manager` مع إبقاء `verify_jwt = true`.
- [ ] التحقق أن Supabase CLI قرأ `supabase/config.toml` وأن وظائف Edge الأربع ظاهرة في لوحة المشروع.
- [ ] ضبط `GEMINI_API_KEY` و`GEMINI_MODELS=gemini-3.7-flash,gemini-2.5-flash` في أسرار Supabase.
- [ ] اختبار جهاز أول، جهاز جديد، الاعتماد والحظر.
- [ ] اختبار كل دور، خصوصًا موزع مسموح/غير مسموح له بإضافة مستفيد.
- [ ] قطع الشبكة والتأكد أن المسودة فقط تُحفظ، وأن كل ترحيل نهائي يُرفض حتى عودة الاتصال.
- [ ] دورة نقدية كاملة: قبض، تمويل، تخصيص، صرف، إلغاء، تحويل.
- [ ] تسوية تخصيص ثم إعادة فتح ومطابقة الرصيد.
- [ ] دورة عينية كاملة مع العكس وفحص المخزون.
- [ ] سؤال Gemini عن شرح شاشة وتقرير وتنقل، ثم إجراء مقترح مع إلغاء وآخر مع تأكيد، ثم اختبار الدليل المحلي عند تعطيل المفتاح مؤقتاً.
- [ ] إنشاء نسخة أعمال V3 متسقة وفحص manifest والأجزاء والبصمات.
- [ ] قطع الاتصال أثناء نسخة V3 متسقة والتأكد من إلغاء الجلسة وتحرير قفل الكتابة، ثم إنشاء نسخة جديدة بنجاح.
- [ ] استعادة V3 بنمط الدمج في التجريبي ثم تشغيل تقرير التكامل المالي.
- [ ] إعادة إرسال طلب إنهاء النسخ وطلب اعتماد استعادة ناجحة والتأكد أن النتيجة تُعاد دون تكرار السجلات.
- [ ] استعادة V3 بنمط الاستبدال المطابق في مشروع تجريبي منفصل ومطابقة الأعداد والأرصدة.
- [ ] تجربة تحويل ملف V2 حقيقي والتحقق من بصمته الأصلية، وتجربة V1 إن وجدت ومراجعة تحذير «نسخة قديمة غير موقعة».
- [ ] التحقق أن التحذير الكهرماني لا يخفي مشكلة مانعة، وأن فشل التكامل النهائي يعيد كل التغييرات ويعطي نتيجة واضحة.
- [ ] إضافة صلاحية صندوق مرة لمستخدم ومرة لموزع، ثم التأكد أن اختيار الاثنين أو عدم اختيارهما مرفوض في الواجهة وقاعدة البيانات.
- [ ] مراجعة روابط المرفقات وStorage وسياسات الحاوية.
- [ ] تشغيل `node --test tests/*.test.mjs` وحفظ النتيجة.
- [ ] فتح `output/pdf/Zaket-V12.2-Executive-User-Guide-AR.pdf` ومراجعته مع المدير قبل التسليم للمستخدمين.
