# قائمة نشر مختصرة

- [ ] مشروع Supabase جديد أو بيئة تجريبية منفصلة.
- [ ] تنفيذ `supabase/database_complete.sql` كاملًا بلا أخطاء.
- [ ] عند الترقية، تنفيذ الكتلة من علامة V12 حتى النهاية دفعة واحدة؛ كتلة V12 معاملة ذرّية واحدة.
- [ ] إنشاء أول مستخدم Auth ثم `bootstrap_first_admin`.
- [ ] ضبط `supabaseUrl` و`supabaseAnonKey` فقط في `js/config.js`.
- [ ] نشر وظائف Edge الثلاث مع `--no-verify-jwt`؛ كل وظيفة تتحقق من الجلسة بنفسها.
- [ ] التحقق أن Supabase CLI قرأ `supabase/config.toml` وأن الوظائف الثلاث ظاهرة في لوحة المشروع.
- [ ] ضبط `GEMINI_API_KEY` و`GEMINI_MODEL` في أسرار Supabase.
- [ ] اختبار جهاز أول، جهاز جديد، الاعتماد والحظر.
- [ ] اختبار كل دور، خصوصًا موزع مسموح/غير مسموح له بإضافة مستفيد.
- [ ] قطع الشبكة والتأكد أن المسودة فقط تُحفظ، وأن كل ترحيل نهائي يُرفض حتى عودة الاتصال.
- [ ] دورة نقدية كاملة: قبض، تمويل، تخصيص، صرف، إلغاء، تحويل.
- [ ] تسوية تخصيص ثم إعادة فتح ومطابقة الرصيد.
- [ ] دورة عينية كاملة مع العكس وفحص المخزون.
- [ ] سؤال Gemini عن تقرير، ثم إجراء مقترح مع إلغاء وآخر مع تأكيد.
- [ ] نسخة V12 واستعادتها في التجريبي ثم تقرير التكامل المالي.
- [ ] مراجعة روابط المرفقات وStorage وسياسات الحاوية.
- [ ] تشغيل `node --test tests/*.test.mjs` وحفظ النتيجة.
