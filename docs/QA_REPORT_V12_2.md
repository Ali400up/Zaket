# تقرير التحقق والجودة — ZAKET V12.2.0

تاريخ الفحص: 2026-08-23

## النتيجة المختصرة

الحزمة اجتازت جميع الاختبارات الآلية المتاحة محليًا، وأصبح النسخ والاستعادة الحيان يمران عبر Supabase Edge Function فعلية باسم `backup-manager` بدل استدعاء دوال V3 مباشرة من المتصفح. أُعيد تصميم دليل الاستخدام العربي وتوليده في 28 صفحة A4 بخطوط عربية مضمنة.

هذا التقرير يثبت سلامة الكود والعقود والحزمة محليًا. لا يدّعي نشر الوظائف على مشروع Supabase حي؛ يلزم مسؤول المشروع تنفيذ أوامر النشر واختبار قبول على بيئة تجريبية قبل الإنتاج.

## ما تم التحقق منه

### النسخ والاستعادة V3

- ثمانية إجراءات Edge ثابتة فقط، مرتبطة بدوال RPC V3 المعروفة.
- قائمة ثابتة لجداول النظام داخل Edge، مع تحقق إضافي داخل PostgreSQL حسب نطاق النسخة.
- تمرير رمز جلسة المستخدم صراحةً إلى `auth.getUser(token)` وتمرير `Authorization` وبصمة الجهاز إلى RPC.
- عدم استخدام `service_role` في `backup-manager` وعدم تجاوز RLS أو `auth.uid()`.
- رفض غياب الجلسة أو بصمة الجهاز أو اسم جدول غير مسموح أو إجراء غير معروف.
- حد أقصى 150 صفًا و450,000 بايت للجزء، وحد مستقل لحجم الطلب.
- تحقق SHA-256، ورفع إلى staging، وفحص preflight، وتأكيد `MERGE-RESTORE` أو `EXACT-RESTORE`، وتنفيذ ذري أو تراجع كامل.
- عدم وجود استدعاء حي مباشر من `data-service.js` إلى `backup_v3_*`؛ جميع العمليات تمر عبر `backup-edge-client.js` و`backup-manager`.
- إعداد `verify_jwt = true` للوظيفة في `supabase/config.toml`.

- لا يحتوي نص الإصدار القديم 12.1.

## قبول Supabase المطلوب قبل الإنتاج

1. ربط Supabase CLI بالمشروع التجريبي الصحيح.
2. تنفيذ `supabase/database_complete.sql` للتثبيت النظيف، أو كتلة الترقية المناسبة فقط للمشروع القائم.
3. نشر الوظائف الأربع، وخصوصًا:

   ```bash
   supabase functions deploy backup-manager
   supabase functions deploy gemini-assistant --no-verify-jwt
   ```

4. التأكد من ظهور `backup-manager` في لوحة Edge Functions ومن وجود سجل استدعاء ناجح.
5. إنشاء نسخة V3 متسقة من حساب مدير على جهاز معتمد.
6. استعادة الدمج في مشروع تجريبي، ثم الاستبدال المطابق في مشروع تجريبي مستقل.
7. تشغيل تقرير التكامل المالي ومطابقة الأرصدة والعينات وسجل التدقيق.
8. اختبار Gemini بمفتاح حقيقي، وسؤال معرفي، وتقرير، وإجراء ملغى، وإجراء مؤكد حسب صلاحية المستخدم.

## حدود الإثبات

لم تتوفر في بيئة البناء جلسة Supabase CLI مخولة للنشر أو مشروع تجريبي يمكن تغيير بياناته، لذلك لم يُنفذ نشر حي أو استعادة فعلية على بيانات المؤسسة. الاختبارات الحالية تمنع الأخطاء البرمجية المعروفة وتتحقق من العقود، لكنها لا تلغي ضرورة اختبار القبول الحي المذكور أعلاه.
