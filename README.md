# نظام الزكاة والتبرعات — 12.5.0

حزمة تثبيت نظيفة بواجهة عربية، وخط تجوال محلي، وتدرجات زرقاء هادئة. أعيد توزيع شاشة الدخول للكمبيوتر، مع نموذج واضح ومتجاوب للهاتف. المساعد يدعم إجراءات محددة قابلة للمراجعة وفق صلاحيات المستخدم.

## ملف قاعدة البيانات

يوجد ملف SQL واحد فقط: `supabase/database_complete.sql`. يحتوي المخطط النهائي والدوال والعروض والصلاحيات وسياسات المرفقات والبيانات التأسيسية. لا يحتوي تعليقات أو كتل ترقية متسلسلة. ينفذ داخل معاملة واحدة ويمنع التثبيت فوق قاعدة تحتوي نظامًا مثبتًا، لحماية البيانات الموجودة.

**الملف مخصص لمشروع جديد بقاعدة فارغة. لا يحول قاعدة موجودة ولا يستبدل بياناتها.** عند نقل بيانات فعلية، اختبر النقل في مشروع منفصل مع المحافظة على معرّفات مستخدمي Auth وعلاقاتهم، واحتفظ بنسختك الكاملة قبل التبديل. نسخة التطبيق لا تنقل كلمات المرور أو أسرار الخدمات.

البيانات التأسيسية المضمنة: 11 حالة صحية، و10 فئات للمستفيدين، و10 وحدات، وعملات YER وSAR وUSD، وفرع وصندوق ومخزن رئيسي، وسجل «فاعل خير». الصندوق يبدأ برصيد صفر؛ لا توجد سندات أو قيود مالية أو مستخدمون تجريبيون داخل SQL. أسعار التحويل 1 و140 و550 هي قيم إعداد طلبها المستخدم، وليست أسعار سوق مباشرة؛ حدّثها قبل العمل.

## التجهيز

1. أنشئ مشروع Supabase جديدًا، وافتح SQL Editor، ونفذ `supabase/database_complete.sql` كاملًا مرة واحدة.
2. أنشئ أول مستخدم من Authentication بالبريد الداخلي `u777123456@zakat.local` وكلمة مرور تحددها؛ استبدل الرقم برقم المدير من 9 أرقام.
3. نفذ الاستدعاء التالي من SQL Editor بعد إنشاء مستخدم Auth، مع كتابة رقمه واسمه الحقيقيين:

   ```sql
   select public.bootstrap_first_admin('777123456','مدير النظام',null);
   ```

4. عدّل `js/config.js`: ضع رابط المشروع الجديد في `supabaseUrl`، والمفتاح العام publishable أو anon في `supabaseAnonKey`، واجعل `demoMode: false`. تأتي الحزمة باتصال فارغ ووضع عرض محلي حتى لا تتصل بمشروع آخر تلقائيًا. لا تضع مفتاح secret/service role أو Gemini في هذا الملف.
5. اربط Supabase CLI بالمشروع، ثم انشر الوظائف:

   ```bash
   supabase functions deploy create-user
   supabase functions deploy reset-user-password
   supabase functions deploy gemini-assistant
   supabase functions deploy backup-manager
   ```

   إعدادات التحقق في `supabase/config.toml`. وظائف المستخدمين والمساعد تتحقق من Bearer token باستخدام Auth، ومن نشاط الحساب واعتماد الجهاز داخليًا. وظيفة النسخ تحتفظ بالتحقق من JWT وبصلاحية المستخدم عند استدعاء PostgreSQL.
6. أضف `GEMINI_API_KEY` إلى أسرار Edge Functions من لوحة المشروع. يمكنك ضبط `GEMINI_MODELS` بقائمة نماذج يدعمها حسابك؛ الافتراضي `gemini-3.8-flash,gemini-3.7-flash`. لا حاجة إلى إدخال المفتاح في المتصفح.
7. ارفع ملفات المشروع إلى استضافة ثابتة تدعم HTTPS. الإعداد المرفق يناسب Vercel. حدّد مجلد المشروع جذرًا للنشر.
8. سجل الدخول، ثم افتح الإعدادات ← حالة النظام. اختبر الأدوار الفعلية والمرفقات والنسخ والاستعادة على مشروع تجريبي قبل نقل العمل اليومي.

## التصميم والاستخدام

- خط Tajawal بأوزان 400 و500 و700 و800 محفوظ في `assets/fonts` مع ترخيصه، والأيقونات والمكتبات المحلية مخزنة مع التطبيق.
- قواعد الدخول في `css/login.css`، وقواعد بقية الشاشات في `css/styles.css`. لم تعد هناك عدة تصميمات متعارضة للدخول.
- حجم الخط قابل للتعديل من الإعدادات، وشريط تمرير صفحة العمل في اليسار، والقائمة المتحركة لا تحجز مساحة في الهاتف عندما تكون مغلقة.
- الهوية والهاتف والمعلومات الخاصة تظهر داخل الشاشات المسموحة. الطباعة تستخدم حقولًا مختارة بأسماء واضحة وتستبعد المعرفات والبيانات الشخصية الحساسة.
- بعد أول تحميل ناجح، تتاح الملفات المحلية دون إنترنت. الترحيل المالي والمساعد الخارجي يحتاجان اتصالًا. المسودات المسموحة تدخل طابور المزامنة.
- الذاكرة المحلية وطابور المزامنة منفصلان حسب مشروع الاتصال. عند الانتقال إلى مشروع جديد لا تُرسل عمليات مشروع آخر إليه تلقائيًا.

## المساعد الذكي

راجع `docs/ASSISTANT_CAPABILITIES.md` للإجراءات المدعومة وحدودها. القراءة تخضع لصلاحيات القاعدة، وكل تعديل يُعرض كاقتراح قبل التنفيذ، والحذف يحتاج تأكيدًا إضافيًا. لا يملك المساعد SQL حرًا، ولا يرفع صلاحية الحساب الحالي.

الدخول والمرفقات ونسخ Storage وGemini خدمات مستقلة عن محرك PostgreSQL؛ نجاح فحص SQL محليًا لا يثبت إعدادها في مشروعك المنشور. سجل الفحوص المحلية وحدودها في `docs/QA_REPORT.md`.

## اختبارات المشروع

الاختبارات السريعة باستخدام Node.js 24:

```bash
node --test --test-concurrency=2 tests/*.test.mjs
```

اختبارات قاعدة البيانات والعمليات الفعلية على PostgreSQL محلي داخل PGlite:

```bash
cd tests/integration
npm ci
npm test
```

هذه الاختبارات تنشئ قاعدة اختبار مستقلة وتستخدم بدائل صغيرة لجداول المنصة، ولا تتصل بمشروعك. لا توجد حاجة إلى تشغيل SQL التجريبي على الاستضافة.
