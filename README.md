# نظام إدارة الزكاة والتبرعات — V11 RC1

نسخة تسليم منقحة للعمل على Vercel + Supabase، مع وضع Demo محلي.

## التثبيت

1. افتح `supabase/database_complete.sql` في SQL Editor داخل مشروع Supabase جديد ونفّذه مرة واحدة فقط.
2. انشر وظيفتي Edge Functions الموجودتين في `supabase/functions/` عند الحاجة لإدارة المستخدمين.
3. عدّل `js/config.js` وضع `supabaseUrl` و`supabaseAnonKey` ثم غيّر `demoMode` إلى `false`.
4. انشر مجلد المشروع على Vercel.
5. بعد ترقية نسخة قديمة، امسح بيانات الموقع أو ألغِ تسجيل Service Worker القديم مرة واحدة.

## قاعدة البيانات

ملف التثبيت الوحيد هو:

`supabase/database_complete.sql`

لا توجد ملفات migrations أو hotfix مطلوبة في هذه النسخة.

## حالة الاتصال

- لا تعتمد الواجهة على `navigator.onLine` وحده.
- في وضع Supabase يتم التحقق من خادم Supabase فعلياً.
- في Demo يتم فحص الإنترنت خارج نطاق Service Worker.
- Service Worker لا يعترض أو يخزن طلبات Supabase أو فحص الاتصال.
- شارة عدم الاتصال عنصر Flex مستقل، لذلك لا تتداخل الأيقونة مع النص.

## الاختبارات المنفذة قبل التغليف

- فحص Syntax لجميع ملفات JavaScript بواسطة Node.js.
- التحقق من عدم تكرار معرفات HTML.
- التحقق من وجود جميع الملفات المحلية المشار إليها.
- التحقق من صحة مسارات imports المحلية.
- مراجعة بنية ملف SQL الموحد: معاملة واحدة BEGIN/COMMIT، توازن dollar quotes، وجود RLS، والتدفقات الرئيسية.

التقرير الآلي موجود في `docs/QA_V11_STATIC_REPORT.json`.

## تنبيه مهم

المراجعة الآلية لا تستبدل اختبار التشغيل على مشروع Supabase حقيقي ببيانات تجريبية وصلاحيات فعلية. قبل الاعتماد الإنتاجي، نفّذ قائمة الاختبار في `docs/QA_V11_RELEASE_CHECKLIST.md`.

## V11 RC7 — رصيد الحملة
- تمويل الحملة النقدي ينقل الرصيد من الصندوق إلى الحملة مرة واحدة.
- سند الصرف النقدي يخصم من رصيد الحملة، ولا يخصم الصندوق مرة ثانية.
- تمويل الحملة العيني ينقل الكميات من المخزون العام إلى مخزون الحملة.
- سند الصرف العيني يخصم حصراً من مخزون الحملة المحددة.
- يمنع الصرف عند عدم كفاية رصيد الحملة أو حصة الموزع.
