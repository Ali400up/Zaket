# نظام إدارة الزكاة والتبرعات — V11.2.0

نسخة موحدة ومراجعة لواجهة عربية RTL مع Supabase، تشمل العمليات النقدية والعينية، ترخيص الأجهزة، الاستيراد من Excel، التدقيق، والعمل التدريبي المحلي.

## ملفات البدء

- `supabase/database_complete.sql`: ملف قاعدة البيانات الكامل والوحيد.
- `supabase/first_admin.sql`: تفعيل أول مدير واعتماد أول جهاز وفق التعليمات داخله.
- `excel_templates/import_templates_v11_2.xlsx`: القالب الموحد للاستيراد في 10 شاشات، مع صفحة تعليمات.
- `docs/USER_GUIDE_DETAILED_V11_2.md`: دليل التشغيل، إضافة إلى الدليل القابل للبحث داخل النظام.
- `docs/MANAGER_NOTES_AND_APPROVED_ANSWERS_V11_2.md`: الأسئلة والإجابات المعتمدة للبنود الـ29.
- `docs/QA_V11_2_REPORT.md`: الاختبارات المنفذة ونتائجها.

## تثبيت Supabase

1. خذ نسخة احتياطية إذا كان المشروع يحتوي بيانات قائمة.
2. على مشروع جديد، نفّذ `supabase/database_complete.sql` كاملًا من SQL Editor. لا يوجد ملف ترقية ثانٍ.
3. من Authentication أنشئ مستخدم Auth لأول مدير بالبريد الداخلي الموضح في `supabase/first_admin.sql`، واختر كلمة مرور قوية ولا تكتبها في SQL.
4. نفّذ `supabase/first_admin.sql` مرة واحدة.
5. انشر وظيفتي Edge Functions من `supabase/functions/create-user` و`supabase/functions/reset-user-password` مع متغيرات Supabase القياسية.
6. ضع رابط المشروع ومفتاح anon/publishable في `js/config.js` واجعل `demoMode: false` للعمل الحقيقي.
7. انشر مجلد المشروع على استضافة ثابتة، ثم افتح النظام من جهاز أول مدير.

لا تضع مفتاح `service_role` في الواجهة. تستخدمه Edge Functions فقط من أسرار الخادم، بينما تعتمد الواجهة على مفتاح anon/publishable وRLS والدوال المقيدة.

يتضمن ملف القاعدة منح Data API الصريح لدور `service_role`، لذلك تعمل Edge Functions أيضًا في مشاريع Supabase الجديدة التي يكون فيها التعريض التلقائي للجداول معطلًا.

## الوضع التدريبي

اجعل `demoMode: true` في `js/config.js` ثم شغّل خادم ملفات محليًا:

```bash
python3 -m http.server 8080
```

افتح `http://localhost:8080`. بيانات التدريب محلية ولا تعدّل قاعدة Supabase.

## أهم قواعد V11.2

- لا يوجد قسم أو جدول مستقل للمبلغ النقدي المسلم للموزع؛ حد الصرف يأتي من تخصيص الموزع داخل الحملة.
- سند الصرف والتسليم السريع يبحثان عن المستفيد من أول الحروف ويحددان الموزع والصندوق والعملة تلقائيًا.
- لا يستطيع أي دور تغيير موزع المستفيد؛ الاستثناء لمدير النظام فقط وبشرط وجود تخصيص صالح.
- تمويل الحملة يخصم من الصندوق مرة واحدة، والصرف يخصم من الحملة والتخصيص دون خصم الصندوق ثانية.
- حفظ السندات العينية والسلال مع تفاصيلها ذري؛ الخطأ في أي تفصيل يعيد العملية كلها.
- رموز الفروع والصناديق والمخازن تنشأ تلقائيًا عند تركها فارغة.
- الترحيل والإلغاء والتسوية تتم عبر دوال قاعدة البيانات مع أقفال وفحص رصيد وصلاحية ومنع تكرار.
- يُعتمد أول جهاز لأول مدير مرة واحدة فقط عندما يكون سجل الأجهزة فارغًا؛ وكل جهاز لاحق يحتاج اعتماد المدير، وتظهر عمليات المدير والمستخدمين في سجل التدقيق.

## مسار العمل النقدي

قبض في الصندوق ← تمويل الحملة ← تخصيص الموزع ← صرف للمستفيد أو تسليم سريع.

- رصيد الصندوق = الافتتاحي + الدائن − المدين.
- رصيد الحملة = التمويل المرحل − الصرف المرحل.
- متبقي الموزع = المخصص − المصروف − المرتجع.
- المتاح للصرف = الأقل بين رصيد الحملة ومتـبقي الموزع.

## مسار العمل العيني

قبض في المخزن العام ← تمويل مخزون الحملة ← صرف سلة أو أصناف للمستفيد.

الأصناف لا تدخل صندوقًا نقديًا، وتبقى مرتبطة بالمخزن والحملة والدفعة والتشغيلة والصلاحية.

## التحقق قبل الإنتاج

الاختبارات الآلية لا تغني عن اختبار القبول على مشروع Supabase تجريبي ببيانات مماثلة للإنتاج. قبل فتح النظام للمستخدمين:

1. اختبر الدخول من جهاز جديد واعتماده وحظره.
2. اختبر كل دور والقوائم المسموحة له.
3. نفّذ دورة نقدية كاملة ودورة عينية كاملة مع الإلغاء.
4. استورد نسخة من قالب كل شاشة مدعومة.
5. طابق الصناديق والحملات والتخصيصات والمخزون مع التقارير.
6. أنشئ نسخة احتياطية واختبر الاستعادة في بيئة تجريبية.

راجع الأعداد الدقيقة والسيناريوهات في `docs/QA_V11_2_REPORT.md`.
